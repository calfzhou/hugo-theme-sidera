# Editor-native Markdown links

Sidera resolves ordinary inline and reference-style `.md` links at build time. Keep
source paths in the editor; Hugo supplies the published URL, including date tokens,
slug, explicit `url`, base path and language. No `relref` conversion, permalink map,
raw-Markdown preprocessing, browser rewrite or additional dependency is required.
Verified on **Hugo 0.166.0**; the hook uses native `PageInner` and link `Position`.

```md
[Read the post](../../journal/connect-the-useful-parts/index.md)
[Its heading](../../journal/connect-the-useful-parts/index.md#give-a-link-a-reason)
[Context][reason]

[reason]: ../../journal/connect-the-useful-parts/index.md#keep-the-surrounding-sentence "Why it matters"
```

In the showcase these links live in `content/notes/reading-list/index.md`. The target
is `content/journal/connect-the-useful-parts/index.md`; its native date is 2026-04-14.
With the site's Journal rule it publishes at
`/journal/2026/04/14/connect-the-useful-parts/`. Without that rule, the **same source**
links resolve to `/journal/connect-the-useful-parts/`. Open Notes → Reading List in
the normal showcase; this is committed content, not just a generated test site.

## Resolution contract

- Paths are relative to the **actual source file directory**, not the published URL
  or logical Page directory. Include `index.md`, `_index.md` or the plain `.md`
  filename as appropriate. Nested storage directories and repeated basenames work.
  Native logical aliases are not substitutes for missing physical filenames.
- Use `/` separators. Encode spaces as `%20` or use Markdown angle destinations
  (`[label](<a file.md>)`). English/Chinese filenames and encoded heading fragments
  are supported. Query strings and fragment encodings survive independently.
- The hook calls native `GetPage` with the resolved absolute content path and
  verifies `File.Path`. It does not search globally by basename. The exact filename
  selects its source language: `index.zh.md` can link explicitly to a Chinese Page
  from English. It does **not** silently replace `index.md` with its translation.
  If a file is mounted into several language sites, the current language wins;
  multiple other-language matches fail rather than selecting one arbitrarily.
- Missing page lookup falls back to exact native page resources, cross-bundle
  resources and global `assets` resources. Cross-bundle files follow the owning
  bundle's native permalink. No glob matching or filesystem body reads are used.
  A Markdown file inside a leaf bundle is generally a **content resource**, not an
  independently published Page; it does not acquire a fabricated article URL.
- Ordinary web paths (without `.md`) are **not** looked up as Pages. `/journal/.../`,
  `../guide/`, HTTP(S), protocol-relative, mail, tel and fragment-only links retain
  their destinations unless a local file resource actually matches. Static downloads
  are best authored with their public `/downloads/...` URLs.
- Raw HTML links and links generated by a shortcode's own HTML are not Markdown
  link nodes. B's [image hook](MARKDOWN.md) now reuses this destination helper for native resources
  and Obsidian dimensions; no advanced inline-attribute grammar is installed.
- The renderer keeps Goldmark's formatted/escaped link label. Parsed title escape
  tokens/entities are decoded once and then HTML-attribute escaped (not Markdown
  rendered). URL escaping remains `html/template`'s safe default; only `tel:` gets
  an explicit safe-scheme allowance. Unsafe protocols remain inert. There is no
  blanket `safeURL`, `safeHTML` or unsafe-renderer enablement.

Moving source files can require correcting relative links. Changing only native
permalink/date/slug/url policy does not. Editor portability is not immutable IDs.
Within opt-in theme docs, relative links follow the one mounted source tree at either
prefix. Physical links across unrelated mount roots/contentDir layouts are **not**
a universal filesystem resolver: use paths in Hugo's mounted content namespace,
and verify a new layout explicitly. The existing contextual-taxonomy loader limits
are unchanged. No full real-site URL/heading migration is claimed.

## Diagnostics and authoring policy

Unresolved `.md` destinations produce the suppressible **`sidera-link-source`**
warning, with the literal destination, source position and resolved content path.
The original href is retained, never redirected to a guessed Page. A known local
file without a native URL is reported separately (excluded, disabled-language or
content-resource input); an unknown path/mount is not falsely called a missing file.
Links leaving the virtual content root are rejected for resolution before any
filesystem hint. Known local `static/` Markdown downloads using a leading `/` are
public URLs, not source errors. Other static mounts/public servers are not crawled.

Default warnings are nonfatal in ordinary `hugo server`; `--panicOnWarning` makes them
strict build failures. For a deliberate public `.md` URL outside known local static
storage, prefer an explicit HTTP(S) URL or a site hook. Native
`ignoreLogs = ['sidera-link-source']` is available for a reviewed exception, but
suppresses the **category**, not one link: do not use it to hide migration mistakes.
No broad fail policy is imposed on legitimate ordinary web paths.

Native headings can optionally be checked with a site/language-only boolean:

```toml
[params]
link_heading_checks = true # default false; not a page/cascade/preset setting
```

This emits **`sidera-link-heading`** when a resolved source Page lacks the specified
native heading (`Fragments.Identifiers`). It is off by default because code-line,
footnote, shortcode and custom HTML IDs are not all native headings. A warning says
“no native heading”, **not** “no element exists”. The test harness independently
checks built heading IDs and destinations, including encoded fragments. Validate
non-heading targets against output separately; arbitrary URL anchors are not crawled.
Renamed legacy Hexo anchors need a P4 manifest/conversion, not guessed normalization.

Excluded pages become linkable only when Hugo supplies a native URL in the selected
build. All-states builds are private validation output, not publication. Draft metadata
still must validate (D-013). A native `build.render=link` URL is Hugo's promise of an
external/other-built destination, not proof this build produced a file.

## Native hook precedence and extension

No `useEmbedded` setting is forced. Hugo's `auto`, `fallback` and `never` all permit
project/theme custom hooks; a project `layouts/_markup/render-link.html` overrides
Sidera normally. **`always` deliberately bypasses every custom hook**, including
Sidera's resolver/diagnostics; do not enable it expecting these features to remain.
A site hook may call `partial "links/destination.html" .` for just the destination,
and `partial "links/title.html" .Title` for title decoding. It owns any extra markup
and its safety. These are small rendering helpers, not a reference/search index.

The embedded hook already resolves the common leaf/branch/plain source examples,
local/global resources and query/fragments. A custom hook is warranted here by
verified gaps: nonexistent physical `plain/index.md` can match `plain.md` logically;
above-root traversal is clamped rather than diagnosed; cross-bundle files under dated
routes remain unresolved; missing sources/headings are silent; tel/title escaping
needs care. Installed embedded source and `always` control builds were inspected.
Its broad `GetPage` lookup for web paths and fragment absolutization are not copied.
H's external-link suffix still decorates links progressively without changing hrefs;
heading markers, TOC, code and image behavior remain independent.

P3-E now adds [content references and local search](DISCOVERY.md). Internally the href-only
helper delegates to `links/resolve.html`, returning the same href and its native target;
link hooks/cards can annotate that identity for the deferred graph. Exact native URLs
are recognized separately without rewriting authored hrefs. A root-level File.Dir `/`
is normalized before source matching. Native source diagnostics and C2 bridge remain.
