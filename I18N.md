# UI localization and content languages

Verified with **Hugo 0.166.0**. Sidera uses native Hugo translation tables, not a
JavaScript registry or frontend framework. English: `i18n/en.toml`. Initial Chinese:
**Simplified Chinese for China**, `i18n/zh-CN.toml`. The catalog is deliberately
region-specific; do not promise Traditional Chinese merely by changing a language key.

## Choose a UI language without translating articles

English is the showcase default:

```toml
defaultContentLanguage = 'en'
locale = 'en-US'
```

For Chinese UI around the **same existing content**, set:

```toml
defaultContentLanguage = 'zh'
locale = 'zh-CN'
```

Existing unsuffixed content now belongs to the Chinese site. Its bodies, titles,
author names and tag identities are not rewritten. This is a UI-language choice,
not automatic content translation. `locale` drives HTML `lang`, translation lookup
and native date/number formatting; `defaultContentLanguage` assigns unsuffixed
content. Changing only `locale` does not change content language assignment.

Use the current native `locale` and `.Language.Name` / `.Language.Locale` APIs,
not deprecated `languageCode` / `.Lang` / `.Site.Languages`. The language key `zh`
with locale `zh-CN` and catalog basename `zh-CN` is runtime-tested. The site's old
`zh-CN` locale intent is preserved without guessing that it must be the Hugo
language key or inventing alias catalogs.

## Optional bilingual content: filename translations

The tested bilingual contract is ordinary local TOML/YAML Markdown in the shared
`content/` directory, with Hugo's **translation by filename** convention:

```toml
defaultContentLanguage = 'en'
# Optional; otherwise English stays at / and Chinese at /zh/.
defaultContentLanguageInSubdir = true
[languages.en]
locale = 'en-US'
weight = 1
[languages.zh]
locale = 'zh-CN'
weight = 2
```

```text
content/
  _index.md
  _index.zh.md
  about.md                         # English only is fine
  field-notes/
    _index.md                      # English title/preset/scope/policy/cascade
    _index.zh.md                   # Chinese title/preset/scope/policy/cascade
    alpha/
      index.md                     # English, or index.en.md
      index.zh.md                  # Optional Chinese counterpart
      sample.svg                   # Native shared bundle resource
    chinese-only/
      index.zh.md                  # A translation need not have an English original
```

Hugo language designators in filenames must be lowercase and match the configured
language **key** (`zh`, not the locale `zh-CN` in this example). Unsuffixed Markdown
belongs only to the default language. Each language's browsing root owns
its own policies, cascades, note membership and tag identities. Translate only what
you actually author; missing articles are not fabricated, and Sidera does not add
a language switcher linking to absent translations.

The native adapter executes per language (`EnableAllLanguages`). Its bounded metadata
walk selects that language's filenames, including translated collection roots;
a leaf bundle in any language remains a leaf, so Markdown resources do not become
notes in another language. Runtime membership still uses actual native Pages and
the nearest-owner helper, not metadata counts. Hugo's `partialCached` cache is
already isolated per site/language; no parallel language cache is introduced.
Tag lookup uses the owner's Site; native `relLangURL` validates root routes, and
all UI links use native Page/Pager URLs. Language prefixes and baseURL subpaths are
verified, including `/en/` + `/zh/` and `/preview/zh/`.

**Boundary:** this is not universal Hugo content-loader parity. Separate per-language
`contentDir` trees, arbitrary mounts, disabled-language combinations, other generated
content and JSON/Org metadata have not been established by these tests. The existing
adapter still walks local `content/`; do not infer directory/mount support from the
UI catalogs. No new duplicated-ID/tag-registry authoring model is required. A wider
loader change needs a concrete fixture and separate evaluation, not a speculative
rewrite. Normal filename translations are supported without changing article routes
apart from Hugo's configured language prefix.

## Site-owned wording and native fallback

Create the matching file in the consuming site's `i18n/` directory. Only override
the desired messages; Hugo merges site values over the theme:

```toml
# i18n/zh-CN.toml in the SITE, not the theme
[appearance]
other = '显示模式'
[tags]
other = '主题标签'
```

An English site override belongs in `i18n/en.toml`. Use the matching locale basename
for Chinese rather than placing an override in a less-specific catalog and assuming
it wins. Hugo searches current locale, current language key, default-language locale,
then default-language key. Missing current-language messages fall back to the
configured default language, **not invariably English**. Missing messages with no
fallback yield an empty string. Sidera supplies both complete catalogs rather than
hard-coded English template/JavaScript fallbacks.

During development run fresh builds with:

```sh
hugo --panicOnWarning --printPathWarnings --printI18nWarnings
```

`--printI18nWarnings` intentionally reports both missing keys and default-language
fallback. `enableMissingTranslationPlaceholders = true` is Hugo's optional diagnostic
mode, not a production theme setting. Site overrides and intentionally missing
scratch translations are tested separately from complete-catalog strict builds.

## Adding or editing a message

- Use `T`/`i18n` in the current render context. Add every key to **both** catalogs.
- Translate complete sentences or labels; don't concatenate English noun/plural or
  sort-order fragments. Date messages include the date, and order messages include
  the pin policy so translators can reorder them.
- For plural messages pass an integer `count` to native go-i18n rules, plus `number`
  formatted with `lang.FormatNumber 0`. English supplies `one` and `other`; Chinese
  uses `other`. Do not format `count` into a string before plural selection.
- Use `time.Format ":date_medium"` for human dates. Native `datetime` values,
  timestamps/order and permalinks remain unchanged. Full translated date messages
  sit inside semantic `<time>` elements; the zero-date alternative is a full message.
- Catalogs are **plain text**. Render through Hugo's HTML/attribute escaping; do not
  apply `safeHTML` to interpolated translations. Titles/tags with quotes, ampersands,
  angle brackets, apostrophes and `$1` are tested as data, not injected markup.
- If future JavaScript creates text, pass rendered/escaped translations through
  data attributes or safe JSON, then use `textContent`; don't add English fallbacks.
  Current appearance/navigation JS changes only enum state, selected options and
  disclosure visibility: all human text is already server-rendered from catalogs.
- CSS must select stable classes/data attributes, not translated ARIA names. There
  is no CSS-generated textual content. Punctuation-only breadcrumb/tree separators,
  native numeric formatting, proper names and internal identifiers are not a second
  language registry. Do not translate authored tag identities or machine enum values.

## Inventory by surface

| Surface | Keys / treatment |
| --- | --- |
| Shell / navigation | `skip_content`, `built_with`, `site_navigation`, `site`, `overview`, `collections`, `browse_collections_tags` |
| Collection kind / homepage | `collection_blog`, `collection_notebook`, `collection`, `collection_overview`, `standalone_page`, `standalone_pages` |
| Notebook tags / breadcrumbs | `tags`, `notebook_tags`, `all_tags`, `all_tags_in`, `browse_tags`, `tag_ancestors`, `collection_tags`, `notes_all`, `notes_subtags` |
| Article / metadata | `on_this_page`, `date_published`, `date_updated`, `date_modified`, `published_undated`, `modified_undated`, `undated` |
| Lists / recent / pins | `article_count`, `order_publication`, `order_modification`, `order_title`, `pinned`, `recent_updates`, `recent_explanation` |
| Pagination / empty state | `pagination`, `page_summary`, `no_articles`, `page_first`, `page_previous`, `page_next`, `page_last` |
| Appearance select | `appearance`, `appearance_dark`, `appearance_light`, `appearance_system`; option values/storage enums remain `dark/light/system` |
| Accessible names | Shared catalog labels above; TOC uses `aria-labelledby` pointing at its translated summary. No separate English SR strings or tooltips. |
| JS / CSS / generated pages | No JS-generated human strings or CSS text; generated hub title uses `tags`. Appearance's selected option supplies its native accessible state. No additional status message. |
| Not translation targets | Sidera/Hugo proper names, authored bodies/excerpts/titles/bylines/tag identities, native URLs/datetimes, classes/data/test IDs, developer build diagnostics. |

The 66-key inventory is checked against template call sites and both catalogs.
The showcase's `tests/check_p2c.py` renders every key with 0/1/2/12,345, tests native
fallback/site overrides/escaping, and runs full existing baseline ownership,
defaults, tags, counts, list order, pager, route, date and asset assertions under
both UIs. Its small bilingual fixture has different counts, pins and membership
per language, a translated nested owner and a Chinese-only leaf with a Markdown
resource. Optional `check_p2c_browser.mjs` reuses the isolated Chrome harness.

Cross-browser/complete screen-reader/WCAG certification, real-content migration and
production publication semantics are separate work. Fresh successful builds remain
authoritative; known watcher inconvenience and harmless empty tags are unchanged.

instead of requiring an enum-specific label for custom presets.
